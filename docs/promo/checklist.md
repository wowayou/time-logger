# 首轮推广 checklist（runbook Phase E）

> 用途：把 Phase E 从「一件模糊的大事」变成一串能勾掉的动作。
> 纪律来源：`docs/launch-runbook.md` Phase E、`docs/decisions.md` D3/D13/D16。
> **发帖动作全部由维护者本人执行**，AI 不代发、不代注册、不碰任何账号。

---

## 0 · 心理前提（读一遍再往下）

- 目标不是「涨」，是**拿到第一个非维护者用户的具体反馈**。D16 定的复盘触发条件就是这个，不是阅读量。
- 首轮推广是**一次性动作**，不是新的日常。发完就回去投简历——`CLAUDE.md` 把「用推广/打磨逃避面试推进」列为这个项目的 #1 风险，而推广恰好是最容易伪装成正事的那种忙碌。
- **不做**：买量、互推、小号顶帖、为推广改产品（真实用户报的阻断缺陷除外）、做落地页活体 mock（SPEC-008 仍 park，除非落地页被证明是转化瓶颈）。

---

## 1 · 发帖前自检（一次性，约 30–45 分钟）

### 1.1 线上状态（每条都点开看，别信记忆）

- [ ] `https://time.eigentime.org/` 打开正常
- [ ] `https://time.eigentime.org/app/` 能记一条、能看到时间轴
- [ ] 「···」底部版本号与线上 `manifest` 一致（**别在这里写死版本号**，发帖当天各查一次：`curl -s https://time.eigentime.org/app/manifest.webmanifest`）
- [ ] **断网**再打开一次 `/app/`：能开、能记、能导出（这是文案里「离线可用」那句的凭据）
- [ ] `/privacy/`、`/en/`、`/en/privacy/` 都能打开（英文渠道要用）
- [ ] 换一台没装过的设备/浏览器打开一次：首屏没有报错、没有空白

### 1.2 素材

- [ ] 配图**只用** `docs/assets/demo-mobile-timeline.png` 与 `docs/assets/demo-mobile-edit-drawer.png`（固定 demo 数据）
- [ ] **绝不**用真机截图——你的真实记录里有公司、项目、个人状态（隐私红线）
- [ ] 需要新图就先造 demo 数据再截，截完登记进 `project_audit.py` 的白名单

### 1.3 文案（逐句核对属实）

- [ ] 按自己口吻改写 `docs/promo/` 里对应渠道的底稿——AI 底稿只是骨架，**原封不动发出去会像 AI 写的**
- [ ] 「自用 N 天」用应用头部真实数字（「记录历程第 N 天」），不要拍脑袋。主页那个数字自己会长（`site/index.html` 的 `data-since`），底稿里的「40 多天」只是写稿当时的下界
- [ ] **不得声称**：市场需求已验证、有多少用户、比某某产品好、未来会做什么功能
- [ ] 不出现公司名、面试进度、真实项目名
- [ ] 两个链接都留：GitHub 仓库 + `https://time.eigentime.org/app/`
- [ ] 明说这是**个人自用工具**、开源（AGPL-3.0-or-later）、无账号无云
- [ ] 找一句能一眼看懂的开头（现成的：「5 秒记下真实做了什么——本地、离线、可信的一天时间线」）

### 1.4 准备回帖素材（**这一步最容易被跳过，但它决定首轮效果**）

先把下面五个答案写好放在手边，发帖后不用现编：

- [ ] **数据在哪？** 只在浏览器 `localStorage`，没有账号、不联网、不追踪；完整备份随时导出 JSON。
- [ ] **能多设备同步吗？** 不能，也**暂时不打算做**。要迁移就导出 JSON 再在新设备导入。
- [ ] **iOS 怎么装？** Safari 打开 → 分享 → 添加到主屏幕（PWA，不上架商店）。
- [ ] **和番茄钟/打卡计时器有什么不同？** 它记的是「刚才那一阵做了什么」这句话，不是按了多久开始/停止；时间归到主线/维持/偏航/未记录四个桶，说不清去向的时间老实显示「未记录」。
- [ ] **会不会哪天收费/关停？** 源码开源、数据在本地、导出不依赖任何服务——即使我停更，你的数据和这份代码都还在。

## 2 · 渠道与节奏（D3 建议顺序）

**一次只开一个战场。** 三个渠道错开 24–48 小时，方便逐个处理反馈；同一天全发只会让你哪个都顾不上。

| 顺序 | 渠道 | 底稿 | 特点 |
|---|---|---|---|
| 1 | **少数派** | `docs/promo/shaoshupai.md`（长文） | 审核制，可能等 1–2 天；写作成本最高，所以先动手 |
| 2 | **V2EX** · 分享创造节点 | `docs/promo/v2ex.md`（中短） | 即时；首页停留时间短，选工作日晚上发 |
| 3 | **即刻** | `docs/promo/jike.md`（短） | 即时；适合放在前两个有反馈之后 |

- [ ] 1 少数派 —— 投稿日期：______ 状态：______
- [ ] 2 V2EX —— 发布日期：______ URL：______
- [ ] 3 即刻 —— 发布日期：______ URL：______

**英文渠道（Show HN / Lobsters / r/selfhosted，底稿在 `docs/promo/en-*.md`）**

D3 当时把英文渠道限定为「只推 dev-story、不推应用」，理由是**应用 UI 是中文**。**v78 之后这个前提已经不成立**——界面、主页、隐私政策都有英文版。所以英文渠道现在可以直接推应用本身。

- [ ] 但**放在中文轮全部结束之后**再开：英文社区的回帖压力和时区都更重，一次只开一个战场这条不变
- [ ] Show HN 的标题不得夸张，正文第一句就说清楚它是什么、不是什么

## 3 · 发帖当天

- [ ] 发出后 30 分钟内自查：链接可点、图能显示、标题无错别字、代码块没串行
- [ ] 立刻把 URL 记进 `docs/promo/posted.md`（渠道 / 时间 / 标题 / URL / 备注）
- [ ] 前 2 小时留在场回复（V2EX、即刻尤其看这个）

### 回帖纪律

- [ ] **不承诺路线图**，尤其是同步、云、多端、上架
- [ ] **不贬低竞品**；被拿来比较时只陈述差别，不评价好坏
- [ ] 收到 bug 报告：先问清复现步骤 → 记进 issue → **不当场承诺修复时间**
- [ ] 收到「能不能加 XX」：感谢 + 记录，**不当场答应**（每一个「好啊」都会变成你欠的债）
- [ ] 遇到不友善：不辩论、不回。**没有任何一条评论值得你搭进去一晚上**

---

## 4 · 发帖后 48 小时

- [ ] 汇总一次信号，只看三样：**GitHub star/watch 变化**、**issue/评论里的具体使用反馈**、**有没有人说"我装了并且用了几天"**
- [ ] 明确知道：**没有留存指标**——应用没有账号、不联网、不埋点，所以「有多少人在用」这件事**在设计上就不可知**。这不是缺陷，是隐私红线的代价，别为了看数据去加埋点
- [ ] 把反馈按三类分进 `docs/promo/posted.md` 的备注：① 阻断缺陷（立即修）② 真实使用摩擦（进候选）③ 功能许愿（登记，默认不做）
- [ ] **出现第一个非维护者用户的具体反馈** → 触发阶段复盘（D16 定的就是这个条件，不是日历）
- [ ] 无论结果如何：**回去投简历**。10 次高质量投递 + 1 个作品集案例是并行的硬约束，不因为推广发生了而暂停

---

## 5 · 红线速查（发帖前最后扫一眼）

- 不贴真实记录截图 / 真实备份 JSON
- 不声称市场需求已被验证、不编造用户数
- 不写公司、面试进度、个人具体处境
- 只留 GitHub 与 `time.eigentime.org` 两个链接
- 不代表任何组织发言；这是个人项目
