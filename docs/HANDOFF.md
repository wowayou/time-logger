## 接手时最该知道的几件事

1. **标签配置有三条判据相反的规则，别把它们抹平**（v82/v83）：① 删除只对**零记录**标签开放，且保存时按最新 `load()` **复算**（sheet 开着时别的标签页记了一条要拦下）；② **已有行**的空名是错误，**草稿行**（`data-new="1"`）的空名是「没建过」，直接忽略；③ `config.mainline` 现在按行重建（行序即数组序），而 `setMainlineLongOk` 只认已在数组里的名字，所以 longOk 写回必须排在数组定稿**之后**——这条顺序依赖有单独的红灯用例锁着。
2. **英文界面的存量守卫**：`SUPPORTED_LOCALES` 加入 `'en'` 让 `resolveLocale` 的 navigator 分支第一次真正生效。`ensureLegacyLocalePinned()` 把「已有数据 + 无 locale 偏好」的设备一次性钉在中文；全新安装才跟随系统语言。**动这块前先读 `tests/locale_legacy_migration.spec.js` 的两条互相咬合的用例。**
3. **标签名是数据不是文案**（SPEC-013 §4.5）：保留标签、默认种子、`LEGACY_ALIASES` 都不随语言翻译——翻了旧备份读不回、桶归类查不中。
4. **现象只在系统动效/系统 UI 参与时出现 → 第一步做跨应用对照**（D23，2026-08-05）：白边追查花了四轮、三个错误假设，前三轮全在自己的 CSS 里找嫌疑人；而「换个 PWA 做同样动作」只要 20 秒，一次就分清了责任。当时的交接验收纪律已写着「归因必须有对照组」——**规则在、却没被执行**，与「gitignore 规则在、却从不生效」同类。
5. **`toBeVisible()` 不保证「在视口里」**（v86 教训，D22）：它只检查元素有非空盒子且未被 `display:none`/`visibility:hidden`——**滚出视口照样通过**。v84 把滚动目标改成出错行、却把提示条留在正文末尾，真机上四个步骤全表现为「点了没反应」，而用例全绿。凡是「用户能不能看见」的判据，用 `expectInViewport`（`tests/v86_fixes.spec.js` 里的写法）比较边界盒与视口的相交关系。层级是：`toContainText` → `toBeVisible()` → **在视口里**。
6. **被动重渲染不能挂在 `pointerdown` 上**（v86）：重渲染会把正在被点的元素换掉，随后的 `click` 落在已脱离文档的节点上、到不了事件委托——**一次点击被自己吞掉**。要在交互时触发重渲染，挂 `click` 的**冒泡阶段**（动作已跑完）或 `scroll`。
7. **改「同一性判据」这类基础比较时，数据层与 UI 层要分开裁决**（v85 教训）：把 `tagKey()` 顺手用进 `normalizeConfig` 的去重，会让存量并存的两种拼写在**加载时**被静默丢掉一个——用户没同意、桶不同还会悄悄改历史归类，而且设置页因此看不到冲突、合并入口反而失效。**判据改严必须同时给出口**，出口在 UI，不在数据层。
8. **测试夹具冻结了 `Date.now()`**（`FixedDate`）：任何用「时钟差」做宽限/节流判据的守卫，在用例里恒为 0 而静默失效——v84 的撤销横幅第一版就踩了，改用定时器才活。写这类判据前先想一下它在冻结时钟下是什么行为。
9. **没有任何写入路径可以代替用户确认**（v87，D24）：`longConfirm` 只能来自用户点「确认」或 config 里的 `longOk`。写入路径若自称「用户已经断言过两端」，先去表单里数一数**用户真正能改的字段有几个**——C7A 就是这么错的：过夜表单里能改的只有起点，两个终点都是程序给的。而且这类自动确认的碰撞是结构性的：它唯一生效的场合，恰恰是段落长到最该问一句的场合。
10. **「挪动占位条」是个会改历史的隐式手势**（v87）：新增记录靠改尾占位条的 `ts` 落库，往前挪是续记（对），往后挪是把一段「确实没记」改写成前一条的标签（错）。v48 给编辑/切分/删除都建了 planner + 预览 + 签名复算，唯独**新增**这条最热的路径没有——它至今仍是就地改字段。再动这条路径时留意这个不对称。
11. **同一个问题不要在两处各答一遍**（v87）：「这一段的右邻是谁」在渲染侧走 `loggedEntriesFrom`、在确认侧走 `sortedEntriesFrom`，不一致了一年多没人发现——因为症状是「按钮没反应」而不是报错。跨日上限那条因此**只写在 `segmentBoundsForEntry` 一处**，让渲染/统计/`rawMins`/确认端点四者共用同一个函数。
12. **性能护栏优先用结构性判据，耗时测量须说明范围**（v87）：「一次年视图 render 读了几次 `timelog.config`」是确定性的；耗时判据在并行 CI 里天生抖（旧 boot ratio 判据已淘汰；现行启动压测使用 loaded − baseline 增量预算，年视图另有耗时与 config 读取次数守卫；v1.5.6 起耗时超预算时换一张新页重量、最多三轮合并取最小，预算不放宽，见 `tests/stress.spec.js`）。抖到没人当真的护栏等于没有护栏。
13. **别人的真实数据是最好的模糊测试语料**（v87）：这四条全部是拿维护者那份 633 条备份把每一天的段重算一遍、跟界面上应该出现什么逐条对照出来的，不是读代码读出来的。下次拿到真实备份先做这件事。
14. **`.first()` 在标签设置里不安全**：主线分组出现后 `.cfg-name` 不唯一（v80 已改三处），v83 的草稿行让它更不唯一——一律按 `data-kind` / `data-original-name` / `data-new` 定位。
15. **配置页的 CAS 基线只在「真正新开 sheet」时捕获**（v1.4.1/R5）：标签高级设置的局部动作（设为当前、添加默认标签）会原地重渲整张 sheet；若这时现读 raw 当基线，另一标签页在 sheet 打开期间的写入会被当成自己的起点而静默覆盖。`saveConfigChecked` 成功后回传落库 raw，调用方把基线推进到写入后的值，否则紧接的第二个局部动作会误判并发。局部重渲前后用 `captureConfigEdits`/`restoreConfigEdits` 抓取回填，草稿的原分组与所选桶分开捕获（改桶不提前跳组）。
16. **标签「归属」提醒与「不改桶」规则是一对，别拆开**（v1.5.0）：已登记标签从不因录入改桶（v30），所以用户在「维持」里敲一个主线名时，记录一定记进主线——这条规则对、不能改；错的是旧提示判据只查 chip 且逐字相等，主线同名与大小写变体都漏。现在判据集中在 `storage.js` 的 `configuredBucketForTag`，表单提醒、草稿 chip 的颜色、「改选 X」三处共用；联想列表也只列所选桶，别再改回「永远联想主线名」——那等于在引路踩坑。
17. **切一刀 / 补一下的选择器是区间，不是两个时刻**（v1.5.0）：`mountRangePicker` 一次挂两端，段外值回弹、日期恒定；两端的 `data-picker-compact` 在同一个挂载点上，跨 720px 重挂只看 `[data-role="backfill-range-mount"]`。它**故意不**强推「开始 < 结束」——一端推着另一端跑时用户找不到自己刚设的值，报错交给 planner 与总览条。比例条是文字行的图示（aria-hidden），可读真源仍是逐段行。
18. **格言/句库的两条教训**（v1.5.0–v1.5.1，D31）：句库在独立键 `timelog.quotes`，启动快照多一道 `quotesRaw` 门（`index.html` 与 `app.js` 两处同步）；备份里的 `quotes` 是可选顶层字段，安卓仓 `docs/DATA-CONTRACT.md` 同步运行时要补上。v1.5.0 声称拆句幂等、断言也绿，但只测了单层记号——嵌套记号让「打开设置什么都不改点完成」删掉整个句库。幂等这类性质要用**组合输入 + 固定种子模糊测试**去证；凡是「拆出来为空就删除」的路径都要区分「用户清空」与「解析出空」。
19. **对外口径、字号圆角令牌都有 audit 硬拦**（v1.5.1–v1.5.2）：新增存储键先改隐私政策、改名先登记旧叫法；令牌外的裸字号/圆角要写 `raw:` 理由并精确调 `CSS_RAW_EXCEPTION_COUNTS`。间距令牌只覆盖 4px 刻度，半档值别顺手「对齐」。Linux 无头截图看不出 650→600 这类字重差，字重相关只能真机确认。规则全文在 `CLAUDE.md`。
20. **标签云的收起/折叠/筛选只是呈现**（v1.5.3，SPEC-017）：编辑控件留在每行 DOM 里，保存事务因此不用改；代价是任何指向某一行的报错都要先 `revealConfigRow` 再聚焦，局部重渲后要把结果拉进视口——v1.5.1「补回默认标签没补回」就是预览在屏幕外。
21. **里程碑庆祝是写入路径上的显式调用**（v1.6.0，D32）：值不值得庆祝取决于谁在写，所以不能包在 `saveChecked` 上（会把导入、撤销、回滚一起算进去）。新增记录写入路径时记得接 `celebrateMilestone`。
22. **结果签名保护不了被草稿覆盖或删除的原记录**（v1.6.1）：草稿先套到最新数据上再比 `resultSignature`，原记录的新文字可能已被覆盖、两个结果反而一样。先比打开时的原记录，再做预览重算与写前检查；删除另存源记录签名。测试要直接断言另一标签页的新原文没被写掉，不能只看签名或提示框。见 [SPEC-018](specs/SPEC-018-reliability-and-summary.md)。
23. **Pages 手动部署成功不证明 tag 发布可用**（D34）：`github-pages` 环境按分支/tag 分别放行，workflow glob 与环境模式语法也不同；两站 workflow 独立，tag 后分别验收。命令与回退只在 [上线操作单](launch-runbook.md#a1a-旧-origin-的-pages-actionsd34)。
24. **正文自动选标签靠「谁动过」三个状态，不靠区分调用来源**（v1.14.0）：`sheet_controller.js` 的 `formAutoTag` / `formTagManual` / `formBucketManual`。`pickTag` / `pickBucket` 既被点击调用、也被联想与「改选 X」程序调用，两者都算用户亲手选（`markTagChoice`）；自动预选本身**不走**这两个函数，只改状态后 `refreshFormTagArea` 重画。所以新增任何「替用户选标签」的入口都不能经 `pickTag`，否则会把自己锁成手动。切桶后**不要**立即按正文重算——既有用例「先点维持再点睡觉」会被重算点亮后再点掉；只在下一次正文输入时重算。
25. **sheet 关闭后的第二下会落到下面的控件**（v1.14.0）：减少动效时 sheet 同步隐藏，默认动效下关闭兜底定时器也可能先于排队的第二下输入执行，双击/连点的第二下于是命中刚露出的控件。防护按「同一处 + 短时 + 双击或触摸」判，鼠标单击必须放行；指针类型取 pointerdown 的，WebKit 触摸合成的 click 自称 `mouse`。复现用减少动效最稳（`tests/v1_14_0_double_activation.spec.js`），默认动效只是概率性。
26. **新建表单的收尾只走 `closeAfterNewWrite`**（v1.15.0；v1.15.1 去掉新建撤销）：它以 `skipDraftCapture` 关表单（否则 `closeFormSheet` 会把刚保存的内容当成草稿留下，重开又填回来）。新增任何新建写入路径都要接它；编辑保存不接。草稿只在内存——任何「顺手持久化草稿」都会触及隐私政策与快照规则，先改政策再说。撤销横幅只属于删除；v1.15.0 曾让新建共用，维护者要求去掉。
27. **tooltip 出界要看 scrollWidth，不只看可见气泡**（v1.15.0）：悬停样式里的 `width: max-content` 立即生效，800ms 延迟只管可见性，`visibility:hidden` 的盒子照样撑宽页面；所以「看不到气泡」不等于没出界。定位只能量真实宽度，别回到 canvas 估算。窄屏核对时若 scrollWidth 莫名变大，先把鼠标移开再测——指针停在右上角就会触发「···」的悬停（这次就是这样被发现的）。

## 已知坑（踩过的，别再踩）

- **时间轴竖脊长短会被读成时长**（v1.8.0 → v1.8.3）：竖脊通高、行行相接，长度天然被读成时长。v1.8.0 混排单/两行被指出「5 分钟计划看起来比 2 小时工作还长」；v1.8.1 改用户三选一、单行严格等高；v1.8.2 维护者明知取舍选「全文」作默认（行高随内容），时长改由右列数字表达，v1.8.3 用尺子刻度取代 4h 满格条（满格条超出缺口像断了、短段只剩一个点）。再动这里：先写清「这个长度/面积在用户眼里代表什么」，出对比图让维护者选，**满格值、阈值这类参数也要单独确认**；刻度不得改成相对刻度。判据在 `tests/v1_8_1_ui.spec.js`（单行等高）与 `tests/v1_8_2_timeline.spec.js`（全文几何、刻度）。v1.11.0–v1.12.0 曾在时间轴底部放全天热力条，v1.13.0 改为首屏统计卡片里的「比例 ⇄ 分布」切换（底部热力条与「更多」开关移除）：维护者说的「热力底部」是一条热力图，不是按行铺底色——后者做了两轮都被否；判据在 `tests/v1_13_0_hero_visual.spec.js`。两个坑：格子是正方形，网格轨道必须 `minmax(0,1fr)`，否则窄屏会被撑出卡片；右上角切换标签必须绝对定位，放进数字行的 flex 流会因 44px 命中区自成一行，默认态卡片高出 56px。细节：链接热区贴死行底会被下一行抢走最底下半像素；链接容器不能窄于「链接数×44px」；`boot()` 每次加载都 `localStorage.clear()`，预置偏好要在 `boot()` 后 `addInitScript` 再刷新。

- **`.seg` 的选中样式只认 `.active`**（v1.8.1）：时间分析的周/月/年分段从 v1.3.0 起给选中项加的是 `.on`，`aria-pressed` 正确、用例也只断言 `aria-pressed`，于是「三个按钮看起来完全一样」存在了一年多没被发现。复用 `.seg` 时选中类名必须是 `.active`；看得见的状态要断言计算样式（选中与未选中底色不同），不能只断言属性。

- **定高面板里的 grid 会把余量摊进每一行**（v1.8.0）：窄屏 `.tall` 表单面板恒定满视口（v43 为键盘稳定性定的，不能改），而 `.form-sheet-body` 是 grid——默认 `align-content: stretch` 把内容以外的高度平均分给每条 auto 轨道，字段间距随屏幕变高而变大，`display:flex` 的分段控件还会被撑成整宽大灰框。宽屏 dialog 是 `height:auto`，所以只在手机上看得见，桌面截图发现不了。正文已改 `align-content: start`；新加的 grid 正文容器同理。回归 `tests/v1_8_0_layout.spec.js` 量的是「下一项顶边 − 本项顶边 − gap − 本项高 − 外边距」，不是固定像素。

- **推广材料不进公开仓库**（D33，2026-10-13）：渠道底稿、发帖记录、视频分镜与录制手册、演示数据生成器及其录屏检查都在本地私有目录 `推广/`（`.gitignore` 整目录忽略）。写文档时别再往 `docs/promo/`、`scripts/`、`tests/` 放这类材料，也别在公开文档里复述推广文案；`project_audit.py` 与 `doc_sync_check.py` 已不再把推广材料当对外表面。迁出不会删掉历史提交/fork/镜像里的旧副本（不重写公开历史）。

- **跨标签提示不能靠「先点已知晓」来绕过遮挡**（v1.6.1）：专项里一度按确认提示后再关表单的流程跑通，但全量又发现标签设置的两条保存路径被同一条顶置提示挡住，说明问题在布局而不是测试操作顺序。现按提示的实际高度（含安全区）给表单留位，宽度/旋转变化时重测，不写死通知高度、不加设备补丁。回归须在提示仍可见时直接点取消/保存，并检查真实命中目标，不能用 `force` 或预先关闭提示蒙混。

- **CSS 简写里不能夹 `inherit`**（v1.5.2 发现）：`font: 600 12px/1.25 inherit` 整条无效、被浏览器静默丢弃，不报错也不影响其它声明——导入冲突按钮因此从 v52（2026-07-10）到 v1.5.1 一直用浏览器默认字体，没人发现。要继承字体族就拆成长写（`font-family: inherit`）；`audit_css_tokens` 现在会把带裸字号的简写拦下。
- **P35 证明不了「规格本身够不够」**：v74 验收时读实现 diff 又抓出两处规格没写的问题。红灯证明保证的是「规格要求的行为在不在」，验收环读 diff 仍然必要。
- **测试本身可能是假的**：v80 的「只追加」红灯第一次没点亮，因为断言只看「预览整体是否包含某名字」，`normalizeConfig` 去重把缺陷盖住了；改成方向性断言（同名必须在「将跳过」行、且**不得**在「将新增」行）才成立。
- **反馈类断言须检查用户实际可见**：文本存在不代表可见；先检查 `toBeVisible()`，需证明在屏幕内时再检查边界盒与遮挡，见上文第 5 条。
- **同一枚硬币的反面（v91）：断言「不该出现」时不能用带自动重试的否定断言。** `toBeHidden()` 会重试到默认 5s 超时，而 info toast 自己 3s 后消失——于是它等到 toast 自然过期再判过，「无条件弹提示」这个红灯照样全绿。凡是判据里含「自动消失/自动收起」的元素，否定断言必须用一次性读取（`isVisible()`），并在注释里写明为什么不存在「还没来得及出现」的竞态。
- **再往前一步（v1.6.0）：一次性读取也只看得到最后一眼。** 导入完成提示 320ms 后会覆盖同一个 `#info-toast`，先亮过的另一条提示（例如误触发的里程碑）就被盖掉了——「导入也庆祝」这个红灯第一次照样全绿。同一个元素可能先后显示多条消息时，在动作之前挂 `MutationObserver` 记下每次变化，最后逐条检查（`tests/v1_6_0_milestones.spec.js` 的 `watchToasts`）。
- **`returnToMore` 会让 sheet「关不掉」**：从「更多」下钻的 sheet，`closeForm()` 是把内容换回「更多」而非 hidden，构成持续性遮挡（详见 SPEC-012 文末实测校正）。写用例时的直接后果：保存后**不要**再点一次「···」，「更多」已经在那儿了；要露出 FAB 得先点「关闭更多菜单」。同一机制的第三面（v1.9.0）：从「更多 → 时间分析」的事项排行跳到某天时，主视图已切过去，`closeForm()` 却把面板换回「更多」盖在上面——下钻要用 `closeAllForms()`（清空返回栈再关），`drill()` 已改；新加「从二级页跳走」的入口同理。
- **时间分析的局部重渲契约**（v1.9.0）：周/月/年/全部、选键、翻页只替换 `[data-role=analytics-content]`；关键词输入框也在这块里，所以打字时**只能**替换 `[data-role=an-items-list]`（`refreshAnalyticsItems` + `buildAnalyticsItemsModel`，只算排行、不算对比/趋势/常态），否则每个按键都会重建输入框、丢焦点与光标，年视图大历史下还会每键重算十几遍整年分段。事项键里含 `\u0000` 分隔符，不能放进 HTML 属性，行按钮用排行里的序号（`data-index`）。
- **端口陷阱（v65）**：`reuseExistingServer: true` 会把 4173 上任何陈旧 server 当被测应用，整套假超时。v1.7.2 本地候选以受控进程成功 `listen` 的 stdout 标记就绪，启动上限 10s，避免未监听端口的 HTTP 预探测挂起；实测占用端口时 EADDRINUSE、未执行测试，不关闭此防护。同一个坑的第二面：全量套件正在跑时再起一个 Playwright 进程会因端口占用直接失败——要临时截图，等全量跑完。
- **`gh pr edit` 会撞 Projects classic 弃用报错**：改用 `gh api -X PATCH repos/<owner>/<repo>/pulls/<n> --input -`；转 ready 用 GraphQL `markPullRequestReadyForReview`。另：`gh pr create --body "$(cat <<'EOF' … )"` 偶发 graphql 连接被重置，改用 `--body-file -` 直接喂 heredoc 更稳。
- `外部/` 已进 `.gitignore` 并已重命名为不带空格（2026-07-27）。原真名尾部带一个空格，而 gitignore 会吃掉行尾空格，旧规则匹配不到它——**规则在、却从不生效**，比没有规则更危险。现为 `外部/` + `外部*/` 两条。

## 首轮可靠性与可达性复核

本轮 R 编号只用于 [本地验收记录](reviews/2026-11-13-local-acceptance.md)，不覆盖 roadmap 的历史 R1–R4。结果统一看 STATUS；截图和合成故障原始证据在本机忽略目录，不放公开资产目录。

- 四桶分钟数相同不能证明原始数据未损：归一化必须保留完整标签数组与原文空白的差异。
- 存储权限拒绝不是配额不足；关键快照用 `load*SnapshotChecked`，对象与 raw 来自同一次读取，严格检查排在源记录/预览/撤销比较**之前**，否则会误报记录不存在或取消撤销。
- 小字热区与 tooltip 共用 `::before` 会互相覆盖；每个时间轴按钮独立占 44×44px。测试保留正文原生点击、按钮中心与相邻段哨兵，不能靠改点击位置掩盖问题。
- 编辑关闭时原焦点元素可能已脱离 DOM：按记录 ID 找替代行；Esc 不能先 cancelEdit 再 closeForm（第二次 teardown 会 blur 刚恢复的焦点）。
- 导入读取失败不得清掉冲突卡或选择；「重新读取并预览」只重算不写入。
- 历史启动超时仍未定位：`tests/startup_fixture.js` 只做被动取证（不改 rAF、不记录正文/存储/完整 URL），`page-unavailable`/`read-timeout` 如实保留；人工阻断只验证取证，不算根因。WSL 网络重配与 ERR_NETWORK_CHANGED 的关联未证实，不要用代理隔离样本冒充根因已解。
- 本机 TLS 隧道离线检查不是线上检查；WebKit 桌面模拟不是 iPhone 真机。

## 入口与表单的交接

- FAB 与底部渐隐层随 `body.sheet-open` 以 opacity 淡出/淡回（v1.7.5），不用 `hidden` 表示临时退场——会污染业务可用性与启动快照；不加计时器或第二份状态。截图要等面板自身 opacity 到 1 才算稳定打开态。
- 私有网络命名空间里只有回环接口时 `navigator.onLine` 为 false，在线用例会正确走离线分支：先检查环境能力，不得为过门禁覆盖 getter 或跳过原用例。

## 选择器布局的边界

- 过夜续记起点不显示「现在」（硬终点已是当前或更早），由 `mountTimePicker(..., { showNow:false })` 表达，跨断点重挂沿用；不要用 CSS 隐藏后仍留键盘操作。
- 单点与段内滚轮都是 160px、行高 40px，`PAD`/`RANGE_PAD` 与 CSS 同步。初始化定位前的 scrollend 不是用户选了第 0 行；几何断言要等选中行就位。
- 桌面日历在文档流内展开：外部点击先完成动作再收起；内部点击按原事件路径判断（日历按钮点击会重建子节点）；旧日历被同步关闭/重挂移除后，下一次事件必须先终止旧监听。回归要在日历展开时直接点正文/标签并检查真实保存。
- 选择器展开后的延迟聚焦要捕获目标与焦点拥有者，用户已转移焦点、目标已重挂或表单已关闭就放弃；逗号并列的 `querySelector` 按元素树顺序匹配。完整因果链见 [P40](postmortems.md#p40--时间选择器延迟聚焦打断输入webkit-补录起点仍是旧值v171-本地)，真机步骤见 [验收单](device-acceptance.md#v171-日期与时间选择器布局)。
