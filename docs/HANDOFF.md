## 已知坑（踩过的，别再踩）

- **P35 证明不了「规格本身够不够」**：v74 验收时读实现 diff 又抓出两处规格没写的问题（unregister 失败静默 reload、武装态 `aria-label` 不跟随）。红灯证明保证的是「规格要求的行为在不在」，验收环读 diff 仍然必要。
- **反馈类断言一律 `toBeVisible()`**：`toContainText` 对 `display:none` 和被遮挡元素照样通过——SPEC-012 那个回归就是这么漏网的。
- **`returnToMore` 会让 sheet「关不掉」**：从「更多」下钻的 sheet，`closeForm()` 是把内容换回「更多」而非 hidden，构成持续性遮挡（详见 SPEC-012 文末的实测校正）。
- **端口陷阱（v65）**：`reuseExistingServer: true` 会把 4173 上任何陈旧 server 当被测应用，整套假超时。
- **`gh pr edit` 会撞 Projects classic 弃用报错**：改用 `gh api -X PATCH repos/<owner>/<repo>/pulls/<n> --input -`；转 ready 用 GraphQL `markPullRequestReadyForReview`。
- `外部/` 已进 `.gitignore` 并已实际重命名为不带空格（2026-07-27）。原真名尾部带一个空格，而 gitignore 会吃掉行尾空格，旧规则 `外部/` 匹配不到它——**规则在、却从不生效**，比没有规则更危险；同一个坑随后又在「以为已重命名、其实没生效」上咬了一次（尾部空格在文件管理器里不可见）。现为 `外部/` + `外部*/` 两条。
- **压测阈值用例 `stress.spec.js` 小压/极压在本机偶发红**（重试即过）：已用未改动代码在同一台机器复现同一条失败，与近期改动无关。它是边缘阈值用例，近期在 chromium/webkit 都飘过——**待单独收拾**（把绝对毫秒阈值改成相对基线，或加预热）。
- **`.sh-grab` 抓手用例在本机偶发红（v78 记录，未解决）**：`ui_smoke.spec.js` 的「mobile more sheet follows the grabber」断言抓手命中区 `boundingBox().height >= 44`，偶发差亚像素而红，重试即过；chromium 侧见过多次。与压测阈值飘是**两回事**（那条测启动耗时，这条测布局尺寸），但性质相同：绝对数值断言卡在边界上。SPEC-014 执行方与验收人分别独立观察到。**待单独收拾**（用 `Math.round` 或给 44px 留 0.5px 容差，别直接放宽阈值——44px 是可点区红线，放宽会让护栏失效）。
- **跨天记录的形态限制（v77 记录，未解决）**：数据层没有「跨天记录」，段=[本点,下一点)，午夜是统计边界；唯一为跨午夜设计的「过夜续记」要求**昨天尾点是未记录占位**。若昨晚尾点是真实记录（例如刷手机到睡着），想把「昨晚到今早都记成睡觉」只能两步手工完成（昨天切一刀 + 今天补空隙）。放宽触发条件＝改 v57 定下的形态判据，回归面大，**需单独立规格**，不要顺手改。
