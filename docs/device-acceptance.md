## A · v82 删除

入口：「···」→ **标签高级设置**

| # | 操作 | 期望 |
|---|---|---|
| A1 | 看常用标签行 | 第二行右侧是「**N 条记录**」，**没有**删除入口 |

## D · v85 标签合并与大小写

> 这一节会**改写记录的标签名**（只在你点「合并」之后）。先确认 0.1 的备份已存好。

| # | 操作 | 期望 |
|---|---|---|
| D1 | 标签设置里把 `Sleep` 改名成 `睡觉`（或你那对中英同义标签）→ 保存 | 出现提示「「Sleep」的 N 条记录会归到「睡觉」，「Sleep」这一行消失」+ 一个「**合并**」按钮；**此时还没写入** |
| D2 | 点「合并」 | 源标签行消失；目标标签**保留自己的桶与超长段免确认**；那 N 条记录改归目标标签 |
| D3 | 回日视图看统计 | 合并前后**总时长不变**，只是归到了同一个标签下 |
| D4 | 如果配置里同时有 `sleep` 和 `Sleep`：直接进设置页点保存 | 直接给出合并提示（用得多的那种拼写留下），不再是死路 |
| D5 | 记一条，自定义标签敲 `SLEEP`（配置里是 `Sleep`） | **不新增标签**；时间轴上显示 `#Sleep`（存的是配置里的权威拼写） |
| D6 | 把你那批英文默认标签（`Meals`/`Wash up`/`Commute`…）逐个并进中文对应标签 | 每次都是「提示 → 合并」两步；并完后设置页只剩一套 |

> **边界**：`睡觉` ≡ `Sleep` 这种**跨语言**等价要手动合并一次——应用不维护同义词表（D21）。

## 白边现状（2026-08-04 第二次录屏后更新）

- **第一次判断**（亮色页面 vs 深色 `background_color`）已被维护者的暗色对照实验**证伪**。
- **v84 的修复**（补齐 `color-scheme` 四处声明）解决的是「UA 按 light 画自己的表面」这一类问题，对暗色下的滚动条/控件颜色仍然必要，**保留**。
- **第二次录屏（v85、亮色、Galaxy S23）定位到新的可疑源**：窗口右缘那道浅色竖条**内部有滚动条滑块**——它是**经典滚动条占用的那条轨道**，而不是系统窗口底色。`styles.css` 的 `html { scrollbar-gutter: stable }` 会把这条轨道**恒定预留**。
- 待办：在窄屏隐藏根滚动条（`scrollbar-width: none` + `::-webkit-scrollbar { width: 0 }`，按宽度断点，桌面保留），然后**再录一次**确认。本地无法复现——headless Chromium 一律是 overlay 滚动条，`--disable-features=OverlayScrollbar` 实测也切不过来（`clientWidth === innerWidth` 恒成立）。
