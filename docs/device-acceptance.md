## 前置

1. 「更多 → 备份与导入 → 存储备份」保存 JSON。iPhone/iPad 优先系统文件面板；Android/桌面通常直接下载，需自选目标可尝试「分享备份」。
2. 通过更新提示加载新版；「更多」底部版本应与本次验收目标及线上 manifest 一致，不写死旧版本号。
3. 合成数据优先在独立测试环境验收；真实记录、备份、截图只留本机，不提交仓库。标签合并会改写记录标签，操作前核对预览与备份。

## 标签设置与暂存

| 操作 | 期望 |
|---|---|
| 删除零记录标签，再撤销或取消整单 | 删除先暂存，保存前可撤销；有记录标签不提供删除 |
| 清空已有标签名并保存 | 报错、聚焦对应行，提示实际在视口内 |
| 新建空草稿后保存 | 视为未创建；保留名「未知」或重复名则报错 |
| 修改已有行与草稿，再点「设为当前」或预览/添加默认标签 | 未保存的名字、桶、免确认、删除态与草稿仍在 |
| 将草稿改到另一个桶，再触发上述局部动作 | 保留原分组与组内顺序、保留所选桶；保存重开才按实际桶归组 |
| 设置页打开期间，另一标签页改配置，再保存或执行局部动作 | 提示冲突，对方配置保留，不静默覆盖 |

## 长段提醒（按现行规则核对）

- 默认关闭：明确标签段按原桶统计，不要求确认。
- 「更多 → 高级」开启后：超过 3h 且未设免确认的段出现待核提醒，**桶与分钟数不变**。
- 过夜续记不得自动盖确认章；已关闭段可确认，确认只清除提醒，边界改变后提醒可重新出现。
- 导入完整备份不替用户开启本机待核开关。

## 通用抽查

- 键盘开合时表单头部可见、面板不跳动；长设置页末行可滚到且可点。
- 主题和语言从「更多」切换；已有标签名不随语言改变。
- 「更多 → 备份与导入 → 导入检查」逐层返回；可见性检查包括是否在视口内及是否被遮挡。
- 删除记录后最多 8 秒可撤销；下一次其它交互或跨标签页修改使撤销结束，直接点撤销本身可恢复记录。
- 后台停留后回前台，或前台被冻结后触摸/滚动，时间更新到当前分钟。
- 系统动效或状态栏问题先做跨应用对照；无头浏览器不能代替真机系统界面验收。

## 白边追查记录（四轮 + 结案）

| 轮次 | 假设 | 证据 | 结论 |
|---|---|---|---|
| 1（v84 前） | 亮色页面 vs 深色 `background_color` 错配 | 首段录屏只有亮色 | 维护者**暗色对照实验证伪**（暗色下白边仍在） |
| 2（v84） | `color-scheme` 从未声明 → UA 按 light 画自己的表面（含合成器基础背景色） | 代码核查：全项目无 `color-scheme` | 已补四处声明。**它管的是颜色，不是占位**——保留，但不是这条白边的解 |
| 3（v85/v86） | **经典滚动条占的轨道** | 第二、三次录屏逐帧放大：那条通高浅色带**内部有滚动条滑块**；`html { scrollbar-gutter: stable }` 还把它恒定预留 | v86 在 `max-width: 719px` 下 `scrollbar-gutter: auto` + `scrollbar-width: none` + `::-webkit-scrollbar{width:0}` |
| 4（2026-08-05 新录屏） | 上一条**可能站不住** | 同一套取样：两段录屏在**静止态**下左右边缘亮度对称（220/220），白边**只在缩放动效期间**出现——与「恒定占位」不符。滑块只在滚动时淡入，退出手势本身就带出一次滚动，故「动效里看见滑块」不能证明它恒定占位 | 第 3 轮结论下早了：那条证据只够说明「动效期间滚动条可见」 |
| **结案（2026-08-05）** | **系统行为** | **对照实验**：维护者在**其他 PWA** 上做同样的退出手势，**白边同样出现**；同时确认在跑 v86、且滚动时右缘已无滚动条 | Chrome/One UI 在窗口缩放期间用**窗口底色**填充未绘制区域，**Web 侧改不掉**。本条关闭，不做 |

**方法论教训（写给下一个接手的人，也写给我自己）**：这条追查花了四轮，前三轮全在**我们自己的 CSS 里找嫌疑人**，一次对照组都没做。而「换个应用做同样动作」只要 20 秒，一次就分清了责任。`docs/HANDOFF.md` 的验收纪律里本来就有「归因必须有对照组」——我知道这条，却没在第一轮用。**下次遇到「只有在某个系统动效里才出现」的现象，第一步就是跨应用对照，不是读自己的 CSS。**

**两处改动的去留**：

| 改动 | 来源假设 | 现状 |
|---|---|---|
| v84 `color-scheme` 四处声明 | 假设 2（UA 按 light 画自己的表面） | **保留**，且理由独立成立：暗色下滚动条、原生控件、文本选中都该跟着主题走 |
| v86 窄屏隐藏根滚动条 | 假设 3（滚动条占位）——**已被证伪** | **保留但换理由**：手机上恒定预留一条滚动条轨道本身就不对（iOS 与多数 Android 都是 overlay）。它**不再是白边的解药**，别在文档或提交信息里那样引用它。若维护者认为丢了滚动位置指示更亏，随时可以回退这几行 CSS |

**本地复现不了**：headless Chromium 一律 overlay 滚动条，`--disable-features=OverlayScrollbar` 实测切不过来（`clientWidth === innerWidth` 恒成立），所以自动化只能锁**声明**（`tests/v86_fixes.spec.js`），视觉判断只有 S23 能给。

## 状态栏那条线（2026-08-04 截图，判为系统侧）

维护者圈出的位置取样：线上方 235.5、线本身 **194**、线下方 238（Y 亮度）。也就是说它是一条**比两侧都暗**的 1px 硬线。而本项目在那一带只画两样东西：`.statusbar-scrim` 的 `--bg` 实色，和它 `::after` 的 `--bg → transparent` 渐变——**没有任何比 `--bg` 更暗的东西**，画不出这条线。判为系统侧（One UI 状态栏分隔线／Android 边到边 scrim）。

可证伪的对照实验（10 秒）：切暗色再看一次。若线仍在、且仍比两侧暗，就是系统画的；若它跟着主题翻转或消失，那才是我们的，回来再查。
