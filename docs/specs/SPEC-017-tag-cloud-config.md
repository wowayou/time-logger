# SPEC-017 · 标签高级设置：标签云 + 就地编辑

> 状态：**已实现**（2026-10-01，v1.5.3，接在 SPEC-016 A 期 v1.5.2 之后）。实测：§1 同一份 35 个标签的数据，正文从 3301px 降到 738px（390×820 一屏放下，验收线 1320px）。真机验收步骤见 `docs/device-acceptance.md`「v1.5.3 标签云」。
> 触发：维护者 2026-10-01「标签很多的时候管理起来太高了，调研并使用更优雅的管理方式」，同日另一台机器的真机验收反馈（补回默认标签没生效、合并两键观感一般、改名后看不出原名）。
> 维护者裁定（同日，三轮选择）：标签云（而不是紧凑列表行或下钻详情页）+ 点开就地编辑 + 标签多时显示搜索框 + 历史主线默认折叠；补回默认标签**保留预览流程、只修可见性**；改名显示前后对比随本单一起做。

## 1. 现状数据

- 35 个标签（主线 13、维持 14、偏航 8）时，设置页正文高 **3301px**，390×820 视口约 4.5 屏；每行平均 **85px**（Playwright 实测）。
- 原因：每行都是常驻的编辑表单（名称输入框、维持/偏航分段、免确认、条数或删除），没在改的标签也占一整块表单的高度。
- 「补回默认标签」失效的根因（实测）：点入口后整张 sheet 原地重渲染，正文滚动归零，预览和「添加」落在视口外最底部（top≈1581px，视口 820px），看起来什么都没发生；此时点头部「保存」，预览不会被应用。

## 2. 设计

### 2.1 标签云

- 每组（主线 / 维持 / 偏航）的标签按 chip 流式排布（`flex-wrap`），外观与「记一条」表单的标签同族：胶囊形、44px 最小命中高度。
- chip 内容：桶色圆点（取代原来的左缘竖脊，跟随分段控件即时变色）+ 名称 + 记录条数（零记录不写数字，改用虚线边，一眼可见可清理的标签）。
- 当前主线 chip 用 accent 浅底，排在主线组第一位。
- 暂存状态显示在 chip 上：改过名显示「原名→新名」，改过桶或免确认加一个 accent 小点，待删除显示删除线并变灰，草稿显示「新」。

### 2.2 点开就地编辑

- 点 chip 后，它原地变成一张整宽编辑卡；卡头仍是这个 chip（再点即收起），卡身是原来那套控件：名称输入、维持/偏航分段或「设为当前」、免确认、条数或删除/撤销。
- 改过名时，卡身显示「原名「blog」」，回答「改名后看不出原来是什么」。
- **一次只展开一张**：点开另一张时，上一张收起，它的暂存改动仍反映在 chip 上。空名草稿收起时直接移除（空草稿本来就视同未创建）。
- 点开时不自动聚焦输入框（移动端会弹出键盘，而用户可能只想改桶）；「＋ 新建」创建草稿时仍聚焦输入框。

### 2.3 历史主线折叠

- 历史主线（非当前）达到 3 个时，主线组只显示当前主线，其余收进「历史主线 · N 个」，默认收起。
- 收起时仍显示的例外：有暂存改动、待删除或正在展开的历史行——折叠不得把改动藏起来。

### 2.4 搜索

- 标签总数达到 12 个时，正文顶部显示筛选框，按 `tagKey`（大小写不敏感）对**原名或当前输入值**做包含匹配。
- 只影响显示：被筛掉的行仍在 DOM 里，照常参与保存。搜索期间忽略历史折叠；没有命中的分组整组隐藏；一个都没有命中时显示「没有匹配的标签」。草稿和正在展开的行始终显示。

### 2.5 出错时把行找出来

保存被拦下（空名、保留名「未知」、重名、删除时发现已有记录）或弹出合并提示时，先把涉及的行亮出来：清空筛选（若它被筛掉）、展开它（若在折叠里也就随之可见），再滚动、聚焦。不得让报错指向一个看不见的输入框。

### 2.6 补回默认标签（只修可见性）

- 点入口：重渲染后把预览滚进视口并聚焦「添加」。
- 点「添加」：写入后滚到第一个新增的标签。
- 预览里点「取消」：焦点回到入口。
- 「头部保存不应用预览」的陷阱仍在，维护者知情选择不改流程。

### 2.7 合并提示文案

- 有一边被改名时，改说「你把「blog」改成了「阅读」，而「阅读」已存在……按「阅读」所在的桶统计」。
- 两边都没动（存量 `sleep`/`Sleep`）时沿用原文案。
- 两键观感归 SPEC-016 B 期的整行按钮收敛，本单不动按钮样式。

## 3. 不变的语义

- 「全部改动在保存时一起写入、取消整单作废」（v83）、`saveTagConfig` 的校验与迁移事务、合并方向与签名复算（D21）、配置 CAS 基线（v1.4.1）、局部重渲染前后的暂存抓取与回填（v1.4.1–1.4.2）全部不改。
- 本单只换呈现与展开状态。抓取与回填额外带上：哪些行展开着、历史折叠是否打开、筛选词。
- 不做：拖拽改桶或排序、多选批量（D20）、同义词识别（D21）、按使用频率自动分层。

## 4. 验收标准

1. 35 个标签（上述构成）在 390×820 下，正文总高不超过原来的 40%（≤1320px，全部收起、历史折叠时）。
2. 点 chip 展开、再点收起；展开另一张时上一张收起，其改动在 chip 上可见（原名→新名 / 小点 / 删除线 / 新）。
3. 改名后卡身显示「原名「…」」，改回原名后消失。
4. 历史折叠：≥3 个历史主线时默认收起；有暂存改动的历史行在收起状态下仍可见；「设为当前」等局部重渲染后，展开状态、折叠状态与筛选词保持不变。
5. 搜索：≥12 个标签时出现；筛掉的行照常保存；没有命中时有提示；出错行被筛掉时会被亮出来。
6. 现有的保存、合并、并发、暂存回填用例语义全部保留（只增加「先展开」这一步）。
7. 补回：点入口后预览在视口内、「添加」获得焦点；添加后第一个新增标签在视口内。
8. 合并提示：改名撞名用新文案，`sleep`/`Sleep` 沿用旧文案。
9. 中英文案对等；双引擎全量通过；矮视口（375×600）最大内容量下最后一项可滚到、可点。
