## 2. 设计原则（执行时的裁决依据）

1. **少即是一致**：每个维度收敛到能数得清的档位——字号 4 档、字重 2 档、圆角 3 档、间距一套 4px 基准刻度、控件高度 2 档、层级一张表。
2. **令牌先于组件**：先让每个裸值找到它的令牌（或被判为正当例外并写注释），再谈组件合并。
3. **不改信息架构**：本 SPEC 只动「同一个东西长得不一样」，不改 header 三行、sheet 语法、时间轴竖脊等已写进 `CLAUDE.md` 的结构红线。
4. **每期都能变红**：每一期收尾都要加一条 audit 或 UI 断言，防止裸值回流（例如「令牌块以外不得出现新的裸字号」）。
5. **截图对照**：每期前后在 320/390/768 × 亮/暗 各截一次固定 demo 数据，人工比对，发现意外变化先停。

## 3. 分期计划

| 期 | 范围 | 用户可见的收益 | 验收判据 | 预估 |
|---|---|---|---|---|
| **A · 令牌收敛** | 字号：补 `--fs-ui-strong`（14px）与 `--fs-title`（17/18 统一），裸 12/13/15 改用令牌，11px 逐处核查（不得低于 12px 用于正文）；字重 600/650 合一；圆角：8/9/10 → 新令牌 `--r-sm`（8）、14 → `--r-ctl` 或说明；间距：引入 `--sp-1…--sp-6`（4/8/12/16/24/32），奇数值逐个改或注释；遮罩与阴影透明度令牌化 | 同级文字、同类控件在不同 sheet 里终于一样大、一样圆 | audit 新增「令牌块以外不得出现新的裸 font-size / border-radius」；截图对照无意外变化；全量双引擎 | 1 个 session |
| **B · 组件清单** | 次要文字动作统一为一个 `.text-action`（合并 mini-btn / range-snap / wheel-now-btn 的视觉，保留各自的触控热区）；整行动作统一 cell-btn / cell-action / cell-danger 的高度与圆角（一个基类 + 变体）；在 `docs/` 写一页组件清单（名称、用途、状态：默认/按下/禁用/焦点） | 「能点的东西」看起来属于同一个应用 | 清单与 `ui.js` 模板里的 class 一一对应（audit 可查「模板里出现未登记的按钮 class」）；键盘焦点环全部可见 | 1 个 session |
| **C · 层级与动效** | z-index 收成一张层级表（令牌化：`--z-sheet`、`--z-fab`、`--z-toast`…）；遮罩透明度统一；过渡时长统一到 `--t-fast` / `--t-base` 两档，全部尊重 `prefers-reduced-motion` | 横幅/撤销提示/FAB/sheet 的遮挡关系可预期 | 现有「提示层级」用例 + 新增一条层级表断言 | 半个 session |
| **D · 文案与空状态** | 按「见名知意」逐条过一遍 zh/en 文案（v1.5.1 已改掉「时间拨号盘」「接通」）；统一空状态、错误提示、成功提示的句式与位置 | 第一次用的人不需要猜 | `RETIRED_PUBLIC_TERMS` 登记被改掉的旧叫法；真机过一遍主要流程 | 半个 session |
| **E · 真机验收** | 按 `docs/device-acceptance.md` 在 iPhone 与桌面各走一遍 A–D 的变化 | 结论来自真机，不来自无头浏览器 | 验收单逐条勾选 | 维护者 |

**顺序依据**：A 是 B/C 的前提（没有令牌就没有统一的变体）；D 可与 A 并行但放在后面，避免同一批既动样式又动文案、回归时说不清是谁造成的。每一期单独发一个 patch/minor 版本。

## 4. 明确不做

- 不引入 CSS 预处理器、Tailwind、组件库、设计工具导出的代码或任何构建步骤。
- 不做主题换肤、用户自定义配色、动画库。
- 不借「设计系统」之名改信息架构或新增功能；新功能仍按 `CLAUDE.md`「v2 锁死 & 别镀金」逐项评审。

## 5. 风险

- **回归面大**：`styles.css` 里有大量「为某个真机问题写的补丁」（P21/P22/P34 等），统一数值时可能把它们一起抹掉。每一处改动前先 `git log -S` 查这个值的来历，带编号注释的值默认保留。
- **视觉变化 ≠ 功能变化，自动化测不到「难看」**：截图对照是人工步骤，不能省。
- **打磨引力**：A–D 加起来约 3 个 session。若求职推进同期没有进展，按 D9 的精神应先停在 A。
