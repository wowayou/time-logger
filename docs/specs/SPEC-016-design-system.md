## 2. 设计原则（执行时的裁决依据）

1. **少即是一致**：每个维度收敛到能数得清的档位——字号 4 档、字重 2 档、圆角 3 档、间距一套 4px 基准刻度、控件高度 2 档、层级一张表。
2. **令牌先于组件**：先让每个裸值找到它的令牌（或被判为正当例外并写注释），再谈组件合并。
3. **不改信息架构**：本 SPEC 只动「同一个东西长得不一样」，不改 header 三行、sheet 语法、时间轴竖脊等已写进 `CLAUDE.md` 的结构红线。
4. **每期都能变红**：每一期收尾都要加一条 audit 或 UI 断言，防止裸值回流（例如「令牌块以外不得出现新的裸字号」）。
5. **截图对照**：每期前后在 320/390/768 × 亮/暗 各截一次固定 demo 数据，人工比对，发现意外变化先停。

## 4. 明确不做

- 不引入 CSS 预处理器、Tailwind、组件库、设计工具导出的代码或任何构建步骤。
- 不做主题换肤、用户自定义配色、动画库。
- 不借「设计系统」之名改信息架构或新增功能；新功能仍按 `CLAUDE.md`「v2 锁死 & 别镀金」逐项评审。

## 5. 风险

- **回归面大**：`styles.css` 里有大量「为某个真机问题写的补丁」（P21/P22/P34 等），统一数值时可能把它们一起抹掉。每一处改动前先 `git log -S` 查这个值的来历，带编号注释的值默认保留。
- **视觉变化 ≠ 功能变化，自动化测不到「难看」**：截图对照是人工步骤，不能省。
- **打磨引力**：A–D 加起来约 3 个 session。若求职推进同期没有进展，按 D9 的精神应先停在 A。

**与计划的偏差**（理由如实记录）：

1. **间距没有「逐个改或注释」奇数值**。实测离刻度值共 169 处：半档 2/6/10/14/18 共 110 处、奇数 1/3/5/7/9/11/15 共 59 处。它们决定每个组件的节奏（如时间轴行 `11px` 上下内边距、分段控件 `7px 9px`），统一到刻度会让整页每个组件都挪 1–2px——那是一次节奏重排，不是「同一个东西长得不一样」的修正，截图对照也会被铺满差异、失去发现意外的能力。这些值没有记录在案的来历，A 期不编造理由逐行注释；顺延到 B 期按组件收敛。
2. **遮罩与阴影透明度没有令牌化**：遮罩只有 sheet 背板一处，阴影透明度已封装在 `--shadow-1/2/3` 里；审计表里「0.35/0.40/0.42/0.50 四档」是把阴影令牌内部值和背板算在了一起。剩下的统一归 C 期。
3. **顺带发现并单独修复一个缺陷**（独立提交，先于令牌提交；v52 引入）：导入冲突三个处理按钮的 `font: 600 12px/1.25 inherit` 整条无效（全局关键字不能作简写分量），Chromium 落回 13.3px Arial、WebKit 落回 16px 默认字体。

**守卫**：`project_audit.py` 的 `audit_css_tokens`——令牌块以外的 `font-size` / `font` 简写 / `border-radius` 必须引用令牌（或 `inherit`/`0`/`50%`），例外须同行 `raw:` 理由注释，例外条数精确等于 `CSS_RAW_EXCEPTION_COUNTS`（字号 5、圆角 1）。同时把旧的「全文出现过 `font-size: 16px`」输入字号判据改为校验 `--fs-input` ≥16px 及输入类选择器的引用。红灯验证：裸字号回流、裸圆角回流、带 `raw:` 的超额例外、摘掉既有例外的标记、旧的无效简写回流、解析器丢输入，六种情形各自变红；`calc()` 包令牌放行；输入判据的令牌调小、`.inp` 丢字号、输入类改用更小令牌、规则改名丢失四种情形各自变红。

**截图对照**：固定 demo 数据 × 320/390/768 × 亮/暗 × 10 个界面（日、周、更多、新建、编辑、切一刀、时间分析、标签设置、导入冲突、日期选择器）共 60 张，逐像素比对。先用「只修缺陷」与「修缺陷前」两套互比验证方法确定性（只有导入界面按钮一行有差异，其余 54 张 0 差异）；令牌改动前后的差异全部落在上表「有意」各行：周视图图例点、sheet 内分组与整行键圆角、导入冲突按钮圆角、时间分析单位字、桌面日期选择器（小字变大使居中弹窗高约 1.5px，整体上移 1px）。日、新建、切一刀三个界面 0 差异。未截到的有意变化：提示气泡、更新横幅、撤销按钮、迁移提示按钮的圆角，以及几处键盘焦点环。截图脚本不进仓库。
