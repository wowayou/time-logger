# 候选路线图

> 本页记录候选与评审边界，不是排期。当前执行项见 [STATUS.md](../STATUS.md)；功能扩张门槛见 [CLAUDE.md](../CLAUDE.md#v2-锁死--别镀金)。达到「28 天真实记录 + 求职有实质进展」只允许重新评审，不自动开工。
>
> 更新：2026-09-24。以下保留原 R 编号，区分已经交付的最小方案与仍未放行的扩张。

## R1 · 性能与内存

以可复现的真实卡顿为前提，先测量再决定优化。v26 的资源体积与早期 Chromium 单引擎毫秒数已不能代表当前版本，不再作为现状引用。

现行护栏在 [tests/stress.spec.js](../tests/stress.spec.js)：启动用加载数据相对空数据的增量预算，完整年视图另测耗时及配置读取次数。它们测量的是自动化环境中的页面路径，不代表 iOS 主屏冷启动。真机冷启动取证见 [故障记录 P33](postmortems.md)。

没有新证据时，不主动做虚拟滚动、模块懒加载、图标瘦身或框架迁移。

## R2 · 降低记录阻力与原生入口

- **已落地的网页最小方案**：v1.4.0 的「正在做：X · 已 Ymin」状态条，展示现有进行中段并可点击编辑；没有增加开始/停止计时模型。范围见 `CLAUDE.md` v1.4.0 记录。
- **安卓例外已放行**：D26 批准独立仓库内嵌 Web 运行时并提供原生入口；进度见 `STATUS.md`，不改变本仓无构建、零运行时依赖的边界。
- **仍未放行**：iOS Widget、锁屏实时活动、快捷指令直达等独立候选。iOS 系统小组件与实时活动需要原生载体，按 D17 评审；网页入口需先证明现有记录流程存在重复摩擦。
- **提醒推送不在当前范围**：不能将 Web Push 写成零后端网页方案；远端推送需要额外服务，触及现行架构与隐私边界。

## R3 · 使用里程碑与全局用户数

**本地替代已实现**：v61 起显示「记录历程第 N 天 · 已记录 N 天」，只从真实、非计划、非占位记录派生。它不等于安装天数、人工判断的有效记录日或全局用户数。

**全局第 N 位使用者不做**：本项目没有后端、遥测或可靠安装计数。GitHub Stars、访问量、下载量不能冒充真实使用人数，也不使用写死数字或设备指纹制造社会证明。未来若提出远端匿名计数，需另行评审架构与隐私边界。
