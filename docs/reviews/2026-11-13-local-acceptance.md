## 环境与停止边界

- Linux 桌面无头 Chromium / Playwright WebKit；Node 24.18.0、Python 3.12.3、已安装且与锁文件一致的 Playwright 1.61.1、TypeScript 7.0.2。未安装依赖，未调用付费工具、外部识别 API 或部署服务。
- UI 服务只绑定 `127.0.0.1:4173`，2 workers，单测 30s，显式 `--retries=0`，最终全量上限 720s；未放宽既有性能预算/断言。旧压测自身的既定测量轮次保留，未新增重试。
- 标准入口一次在启动插件超时，隔离复现未监听回环端口的探测不返回；确认未经过代理，但底层网络根因未定位。改为**本受控进程成功 listen 后**发就绪标记，启动上限 10s；实测陌生 server 占用 4173 时 1.089s 内 EADDRINUSE、零测试运行，不复用旧服务。这不是应用启动异常的根因证明。

## 发现与补修证据

- 暗色 FAB 主/副文字原为 **2.31 / 1.96:1**，选中日期/勾选白色同样低；未勾选边界 **1.16–1.28:1**，待删除「撤销」被整行 opacity 拉低到 **2.21–2.76:1**。新增 `--on-*` 主题令牌、清晰边界、不再整行淡化可操作文字。最终 Chromium 实际合成：亮 FAB 主/副 **6.816 / 4.834:1**，暗 **8.291 / 5.600:1**；日期 **6.816 / 8.291:1**。勾选状态/分页图形按必需状态 3:1 分别检查，非统一套 4.5。
- tooltip 的隐藏 `::before` 使「补一下」扩展热区不可命中；第一版补修又被下一行覆盖底部 3px。最终移除文字链重复 tooltip，元信息行预留完整目标高度，命中与正文操作分别守护。全量发现的计划编辑用例原点行中心会触发行内完成：仅把两份旧保护测试的定位改为 `.e-what`，不改原数据/草稿断言；另加正文命中不变更计划哨兵。
- 320px 长标签原右缘约 **851px**，根 scrollWidth 仍是 320（body 隐藏了溢出）；现约束并换行、移除根横向隐藏。桌面长表单原超底部 **12px**，现同时扣除上下留白/通知，保留安全区上限。没有设备名特判。
- 键盘焦点用例补修前红；取证表明编辑打开已更换原行、关闭后又重绘，Esc 还会先 cancelEdit 再 closeForm。现按仍存在的 ID 解析替代行，重绘保焦点，Escape 只派发一次当前层关闭，不抢表单控件。
